# /research コマンド｜キーワードリサーチ手順書

## 入力

```
/research [メインKW]
```

例：`/research Webライター 向いてない`

---

## Step 1: 検索意図の分析

KWから以下を推定する。

```
顕在ニーズ : KWで調べている読者が表面上求めているもの
潜在ニーズ : 本当に解決したいこと（KWの裏にある悩み）
検索意図分類: Know（知りたい）/ Do（したい）/ Buy（買いたい）
```

---

## Step 2: Yahoo知恵袋から読者の声を取得

以下のURLをWebFetchで取得する。

```
https://chiebukuro.yahoo.co.jp/search?p=[KWをURLエンコード]&search=1
```

取得後、以下を抽出する。

- 質問タイトル（読者の生の悩み）
- 回答の傾向（何が解決策として挙げられているか）
- 感情ワード（「しんどい」「向いてないかも」など）

知恵袋が取得できない場合はスキップし、Step 3へ進む。

---

## Step 3: 競合記事のWebFetch

ユーザーにGoogleで「[メインKW]」を検索し、上位5件のURLを提供するよう依頼する。

```
「[KW]」をGoogleで検索して、上位5件のURLを貼り付けてください。
```

URLが提供されたら、各ページをWebFetchで取得し、以下を抽出する。

| 抽出項目 | 内容 |
|---------|------|
| タイトル | 記事タイトル |
| H2・H3 | 見出し構成の一覧 |
| 文字数（概算） | 競合の記事ボリューム |
| 強み | 他の競合より優れている点 |
| 弱み | 一次情報の欠如・抽象的な内容など |
| CTAの有無 | アフィリエイト・内部リンクの配置 |

---

## Step 4: me.mdと照合（一次情報マッピング）

`me.md` を読み込み、KWに関連する体験・数値を抽出する。

```
□ 使える数値（§2）
□ 使える体験談（§4）
□ 使える感情メモ（§5）
□ 使える具体エピソード（§6）
```

「競合が書けないが著者には書ける情報」をリストアップする。

---

## Step 5: 内部リンク計画

既存記事の中から、この記事に自然に誘導できるものを選ぶ。

既存記事一覧（2026-05現在）：
- 記事1：Webライター副業の始め方 → https://tsuzuku-lab.mods.jp/wordpress/web-writer-beginner-guide/
- 記事2：ライティング副業とは？仕事内容・収入・1日の流れ → https://tsuzuku-lab.mods.jp/wordpress/writing-job-content-income-schedule/
- 記事3：副業webライターはやめとけ？ → https://tsuzuku-lab.mods.jp/wordpress/web-writer-yameto-ke/

配置候補と自然な文脈を提案する。

---

## Step 6: research.mdを出力

`drafts/article-XXX/research.md` に以下の構造で出力する。

```
# research.md｜記事[番号]「[タイトル案]」

## 検索意図分析
- 顕在ニーズ：
- 潜在ニーズ：
- 分類：

## 知恵袋の声（読者の生の悩み）
- [質問1]
- [質問2]
- ...

## 競合記事分析
### 競合①：[タイトル]
- H2/H3構成：
- 強み：
- 弱み：

### 競合②〜⑤：（同形式）

## 一次情報マッピング（me.mdから使えるもの）
- 数値：
- 体験談：
- 感情メモ：

## 競合が書けない・著者だけが書けること

## 内部リンク計画
```

---

## 注意事項

- WebFetchで取得できないページはスキップし、取得できたページで分析を進める
- me.mdに記録のない体験・数値は「使えない」と明記する（捏造禁止）
- research.mdはユーザー確認後に `/outline` へ進む
