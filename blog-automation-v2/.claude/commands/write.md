# /write コマンド｜本文生成手順書

## 前提条件

`drafts/article-XXX/outline.md` がユーザーの承認を得ていること。
未承認の場合は「先に /outline で構成案を承認してください」と返す。

---

## Step 1: 読み込むファイル（この4つのみ）

```
drafts/article-XXX/outline.md   ← 承認済みの構成
me.md                            ← 著者の体験・数値（事実の唯一の源泉）
assets/04_tone-sample.md         ← 著者の文体DNA
assets/01_ng-words.md            ← 禁止表現リスト
assets/08_my-templates.md §2§5§7§8 ← PREP法・リード文・本文・まとめのルール
```

07_style-references.md と 02_persona.md は /outline で使用済み。/write では読まない。

---

## Step 2: 生成前の確認

以下を outline.md から読み取る。

- メインKW
- H2・H3の一覧
- CTA配置箇所（リード直下・まとめ後など）
- 内部リンク配置箇所
- 吹き出し配置箇所

---

## Step 3: 本文生成ルール

### H3ごとの生成手順（PREP法）

各H3を以下の順番で書く。

```
P（Point）  : H3見出しの結論を1〜2文で先出し
R（Reason） : なぜそうなのか、理由を1〜2文
E（Example）: me.md から体験・数値を1つ引用（捏造禁止）
P（Point）  : 読者が取れる具体的なアクションで締める
```

**EがないH3は生成しない。** me.mdに該当する体験・数値がなければユーザーに確認を求める。

### 文体ルール（04_tone-sample.md 準拠）

- 1文60〜80文字以内。超えたら分割する
- 1段落150文字以内
- 語尾3連続禁止（体言止め・短文を混ぜる）
- 「〜だと思っています」は1記事3回まで。連続使用禁止
- 感情→データの順で書く（「キツかった。時給12円でした。」）

### 禁止（01_ng-words.md 準拠）

生成後に以下を必ず確認する。

- 「〜することが大切です」「〜することが重要です」→ 削除
- 「非常に」「とても」（強調目的）→ 削除
- 「誰でも簡単に」「すぐに結果が出る」→ 削除
- 「いかがでしたか」「ぜひ参考にしてみてください」→ 削除
- 「〜と言えるでしょう」「〜ではないでしょうか」→ 削除

---

## Step 4: リード文の生成（H2生成後に最後に書く）

08_my-templates.md §5「リード文テンプレート」の6ステップに従う。

```
1. 共感文   : 読者の内声を先取り
2. 問題提起 : なぜそうなるか
3. 権威性   : 著者の実績数値（me.md §2から引用）
4. 本文要約 : 1文で何を学べるか
5. メリット : 読後の理想状態
6. 結論先出し: アンサーファースト
```

500文字以内。

---

## Step 5: CTA・内部リンクの挿入

outline.md で指定された配置箇所に挿入する。

- CTA：`【CTA：クラウドワークス登録ボタン】` と記載
- 内部リンク：記事タイトルとURLを outline.md から転記

---

## Step 6: 出力と草稿宣言

完成した本文を `drafts/article-XXX/body.md` に出力する。

**出力時に必ず以下を付記する。**

```
---
## ユーザー確認事項（草稿）

この body.md は草稿です。以下をユーザーが確認・加筆してからコミットしてください。

□ 口語表現・フランクな言い回しを加筆する
□ 体験談に深みが足りない箇所を加筆する
□ AI感が残っている箇所を自分の言葉に書き換える
□ 上記が完了したら「OK」と伝えてください
---
```

---

## Step 7: ユーザーOK後にコミット

ユーザーから「OK」を受け取ってから `git commit` する。
OK前にコミットしない。
