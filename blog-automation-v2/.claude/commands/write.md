# /write コマンド｜本文生成手順書 v2.0

## 前提条件

`drafts/article-XXX/outline.md` がユーザーの承認を得ていること。
未承認の場合は「先に /outline で構成案を承認してください」と返す。

---

## Step 1: 読み込むファイル（この順番で全て読む）

```
drafts/article-XXX/outline.md      ← 承認済みの構成
drafts/article-XXX/research.md     ← 差別化ポイントの確認（Step2で使用）
me.md                               ← 著者の体験・数値（唯一の一次情報源）
assets/04_tone-sample.md            ← 著者の文体DNA
assets/01_ng-words.md               ← 禁止表現リスト
assets/08_my-templates.md §2§5§7§8 ← PREP法・リード文・本文・まとめのルール
```

---

## Step 2: 差別化ポイントのH2独立チェック（必須・執筆前に実行）

research.md の「差別化の余白」または「判断ログ」セクションを読む。
**採用済みの差別化ポイントは、必ず独立したH2として outline.md に含まれているか確認する。**
含まれていない場合は、執筆を始める前にユーザーに報告して確認を求める。

---

## Step 3: リード文（穴埋め式テンプレート・順番厳守）

**文字数：300〜400字。絶対に超えない。**

以下のテンプレートに沿って穴埋め形式で書く。順番の変更・省略・追加は禁止。

```
【① 共感（1〜2文）】
→ 読者が検索する瞬間の感情・状況を代弁する。

【② 読者の問い（箇条書き3点）】
→ 「こんな疑問を持っていませんか？」として3点を箇条書きで提示。
  ・〇〇なのか？
  ・〇〇なのか？
  ・〇〇なのか？

【③ 権威性（1〜2文）】
→ me.md の数値・属性のみ使用。捏造禁止。

【④ 記事の要約とメリット（1文）】
→ 「この記事を読むと〇〇がわかります」の形で読者のベネフィットを提示。

【⑤ 結論アンサーファースト（1〜2文）】
→ 記事の核心的な答えを先出しする。

【⑥ CTA①（リード直下）】
```

**禁止事項：**
- ストーリー優先でリード文を書かない
- テンプレートの順番を変えない
- 600字以上書かない
- 箇条書き3点を省略しない

---

## Step 4: 各H3の生成（PREP法・順番厳守）

各H3を**必ずこの順番**で書く。体験（E）から入ることは禁止。

```
P（Point）  : H3見出しの結論を1〜2文で先出し。（最初に書く）
R（Reason） : なぜそうなのか、理由を1〜2文。
E（Example）: me.md から体験・数値を1つ引用。（捏造禁止）
              me.mdに該当する体験・数値がなければ停止してユーザーに確認を求める。
P（Point）  : 読者が取れる具体的なアクションまたは結論で締める。
```

**NG例（体験から入っている）**：
「Webデザインで失敗したんですが……結局リサーチが大事でした」

**OK例（Pから入る）**：
「リサーチが苦痛だと続きません（P）。記事の7割は調べる仕事だから（R）。実際Webデザインで……（E）。だからリサーチへの抵抗感ゼロが最低ライン（P）」

---

## Step 5: 文体ルール（04_tone-sample.md 準拠）

- 1文60〜80文字以内。超えたら分割する
- 1段落150文字以内
- 語尾3連続禁止（体言止め・短文を混ぜる）
- 感情→データの順で書く（「キツかった。時給12円でした。」）
- 「〜だと思っています」は1記事3回まで。連続使用禁止

---

## Step 6: 禁止表現（01_ng-words.md 準拠）

- 「〜することが大切です」「〜することが重要です」
- 「非常に」「とても」（強調目的）
- 「本記事では〜について解説します」
- 「いかがでしたか」「ぜひ参考にしてみてください」
- 「〜という点が挙げられます」「〜と考えられます」
- PREP法違反（体験Eを最初に置く）

---

## Step 7: 視覚装飾の最低要件（スマホ最適化）

文章のベタ書きが500文字以上続く場合は、表・箇条書き・吹き出しのいずれかを必ず挟む。

| 要素 | 最低使用数 |
|---|---|
| 表（2列以上） | 3枚 |
| 箇条書き | 5箇所 |
| 吹き出し（読者↔著者セット） | 4組 |
| チェックリスト | 1枚 |

---

## Step 8: まとめの構成

① 要点整理（表またはチェックリスト形式）
② 読者への一言（感情に寄り添う。説教しない。綺麗事で締めない）
③ CTA②（まとめ後）

「いかがでしたか？」「ぜひ参考に」は絶対禁止。

---

## Step 9: 生成後セルフチェック（出力前に必ず実行）

一つでも×があれば修正してから出力する。

- [ ] リード文が300〜400字以内か
- [ ] リード文が①共感→②箇条書き3点→③権威性→④要約メリット→⑤結論→⑥CTAの順になっているか
- [ ] 差別化ポイントが独立H2として含まれているか
- [ ] 全H3がP→R→E→Pの順になっているか（体験Eから始まっていないか）
- [ ] 表が3枚以上あるか
- [ ] 吹き出しが4組以上あるか
- [ ] NG表現が含まれていないか
- [ ] 1文が80文字を超えていないか
