# /write コマンド｜骨格生成手順書 v3.0

## このコマンドの役割

Claude が生成するのは「構造・データ・ファクト」のみ。
声・感情・口語・体言止めはユーザーが乗せる。
出力は「骨格ドラフト」であり、完成稿ではない。

---

## 前提条件

`drafts/article-XXX/outline.md` がユーザーの承認を得ていること。
未承認の場合は「先に /outline で構成案を承認してください」と返す。

---

## Step 1: 読み込むファイル（この順番で全て読む）

```
drafts/article-XXX/outline.md      ← 承認済みの構成
drafts/article-XXX/research.md     ← 差別化ポイントの確認（Step2で使用）
me.md                               ← 著者の体験・数値（唯一の一次情報源）
assets/tone-sample.md              ← 著者の文体DNA（記事4が基準）
assets/01_ng-words.md               ← 禁止表現リスト
assets/08_my-templates.md §2§5§7§8 ← PREP法・リード文・本文・まとめのルール
```

---

## Step 2: 差別化ポイントのH2独立チェック（必須・執筆前に実行）

research.md の「差別化の余白」または「判断ログ」セクションを読む。
採用済みの差別化ポイントは、必ず独立したH2として outline.md に含まれているか確認する。
含まれていない場合は、執筆を始める前にユーザーに報告して確認を求める。

---

## Step 3: リード文の骨格生成

**出力形式：マーカー付き骨格。ユーザーが声を乗せる箇所は【USER】で明示する。**

```
【USER: 共感ライン】
→ 読者が検索した瞬間の感情・状況を「」で直引用する形式。
   骨格メモ: [検索キーワードから読み取れる読者感情を1行で記述]

【USER: 転換＋結論先出し】
→ 「でも先に〜」「ただ正直に言うと〜」の形で核心を先出しする。
   骨格メモ: [記事の核心的な答えを1文で記述]

【自動生成: 権威性】
→ me.md §2 の数値・属性をそのまま引用する。捏造禁止。
   [例: 3ヶ月で月8,000円・継続案件1件・5回副業挫折]

【自動生成: 記事概要（箇条書き3点）】
→ この記事で書くことを3点で提示する。outline.md の構成から抽出。
   ・〇〇
   ・〇〇
   ・〇〇

【自動生成: アンサーファースト（1文）】
→ 記事の核心的な答えを先出し。research.md の結論から引く。

【自動生成: CTA①】
→ outline.md に指定されたCTA文言・リンクをそのまま配置。
```

**文字数目安：全体300〜400字。自動生成部分だけで200字以内に収める。**

---

## Step 4: 各H3の骨格生成

各H3を以下の形式で出力する。【USER】マーカーの部分はユーザーが書く。

```
### [H3見出し]

**P（結論）**
[H3見出しの結論を1〜2文。ファクトベースで書く。感情表現は入れない。]

**R（理由）**
[なぜそうなのか、理由を1〜2文。論理ベースで書く。]

**【USER: 体験・感情】**
→ me.md の該当データ: [該当する体験・数値を原文のまま引用]
→ ユーザーがここに声・感情・口語を乗せる。
→ me.md に該当データがなければこのマーカーごと削除し、ユーザーに確認を求める。

**P（アクション・結論）**
[読者が取れる具体的なアクションまたは結論を1文。]
```

---

## Step 5: 表・チェックリストの生成

research.md と me.md のデータを使い、以下を自動生成する。

| 要素 | 最低数 | 内容 |
|---|---|---|
| 表（2列以上） | 3枚 | データ・比較・相場など facts ベース |
| 箇条書き | 5箇所 | チェックリスト・手順・特徴リスト |
| チェックリスト | 1枚 | まとめセクション用 |

吹き出しは生成しない。ユーザーが肉付けの段階で追加する。

---

## Step 6: 禁止表現（01_ng-words.md 準拠）

- 「〜することが大切です」「〜することが重要です」
- 「非常に」「とても」（強調目的）
- 「本記事では〜について解説します」
- 「いかがでしたか」「ぜひ参考にしてみてください」
- 「〜という点が挙げられます」「〜と考えられます」

---

## Step 7: まとめの骨格生成

① 要点整理（表またはチェックリスト形式）← 自動生成
② 【USER: 読者への一言】← ユーザーが書く
③ CTA②（まとめ後）← 自動生成

---

## Step 8: 生成後セルフチェック（出力前に必ず実行）

- [ ] リード文の【自動生成】部分が300字以内か
- [ ] 差別化ポイントが独立H2として含まれているか
- [ ] 全H3に【USER】マーカーが入っているか
- [ ] me.mdにない体験・数値を捏造していないか
- [ ] 表が3枚以上あるか
- [ ] NG表現が含まれていないか
- [ ] 1文が80文字を超えていないか（自動生成部分のみ対象）
