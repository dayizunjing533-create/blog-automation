# /outline コマンド｜構成案生成手順書 v1.1

## このコマンドの役割

リサーチ結果をもとに記事の骨格（H2/H3構成）を生成し、
生成後に**ユーザーへ一次情報の質問リストを提示する**。
ユーザーの回答を受けてから /write に進む。

---

## 前提条件

`drafts/article-XXX/research.md` が存在していること。
なければ「先に /research を実行してください」と返す。

---

## Step 1: 読み込むファイル

```
drafts/article-XXX/research.md        ← リサーチ結果・差別化ポイント
assets/02_persona.md                   ← ターゲット読者の定義・感情・読後状態
assets/08_my-templates.md §0§1§2§3§6  ← 3つのNOT・検索意図・PREP法・タイトル・見出しルール
assets/07_style-references.md          ← 競合記事の構成パターン（構造参考のみ）
assets/01_ng-words.md                  ← 禁止表現リスト
CLAUDE.md §4-1                         ← 構造設計の5原則（必須チェック）
CLAUDE.md §5-1                         ← リード文テンプレ（骨格生成の基準）
CLAUDE.md §5-2                         ← まとめテンプレ（H2-まとめの設計基準）
CLAUDE.md §5-3                         ← タイトル・スラッグ・メタのルール
CLAUDE.md §5-4                         ← 属性分岐CTAテンプレ
```

---

## Step 2: 構成案の生成ルール

### タイトル（CLAUDE.md §5-3）
- **28〜32字**（モバイル切れ防止）・メインKWを前半30%以内に配置
- 数字を1つ以上含める（「7選」「3つ」等）
- ベネフィットを明示（「対処法」「判断基準」等）

### リード文の骨格（CLAUDE.md §5-1 に従う。本文は書かない）
- 共感 → 悩みへの深掘り → 権威性 → 読者メリット → 結論 → CTA①
- KWの複数属性が混在する場合は「この記事は〇〇な人向けです」とターゲット明示

### H2/H3構成
- research.md の「採用済み差別化ポイント」を必ず独立したH2に含める
- 読者の検索意図（顕在・潜在）を全てカバーする
- H2は4〜6個、H2あたりH3は2〜4個
- 最後のH2は必ず「まとめ」（CLAUDE.md §5-2 に従い H3なし・プロース+箇条書き+CTAボックスのみ）
- CTA設計：複数属性混在KWは §5-4 の属性分岐テンプレを使う

### 各H3の説明欄
各H3に以下を記載する：
- この見出しで伝えること（1行）
- 使う予定のデータ・ファクト（research.mdから）
- 【要一次情報】フラグ：ユーザー体験が必要な箇所はこのフラグを付ける

---

## Step 2.1: 5原則チェック（CLAUDE.md §4-1）

構成案を確定する前に、以下の5原則を全て検証して結果を併記する。

```
【5原則チェック】
✅/❌ 原則1：H2の並びが読者感情の遷移（不安→診断→判断→解決→行動）に沿っているか
✅/❌ 原則2：KWの「本能的な悩み3つ」に全て答えるH2が存在するか
✅/❌ 原則3：自己診断・選択系テーマで対比軸が2セット用意されているか
✅/❌ 原則4：差別化が「著者の個性」ではなく「読者の盲点」を埋める方向か
✅/❌ 原則5：複数属性KWでCTAが属性別に分岐しているか（単一ターゲットの場合はリード文でターゲット明示済みか）
```

❌ がある場合は構成を修正してから次に進む。

---

## Step 2.5: 構成の意図（ペルソナ起点）の出力（CLAUDE.md §8-2）

H2/H3構成を出力したら、**そのまま続けて**以下の表を出力する。
02_persona.md の「本音」「置かれている状況」「読後に目指す状態」を参照して記入する。

```
## 📋 構成の意図（ペルソナ起点）

| H2番号 | タイトル（省略可） | 対応するペルソナの感情・課題 | この構成で起こす変化 |
|---|---|---|---|
| H2-1 | ... | ペルソナの「恐怖」「疑問」などを引用 | 読後状態への橋渡しを1行で |
| H2-2 | ... | ... | ... |
（H2の数だけ行を追加）

読者の感情フロー：
[現在地の感情] → [H2-1通過後] → [H2-2通過後] → ... → [読後状態]
```

ルール：
- 02_persona.md の「本音」欄の【恐怖】【焦り】【疑問】【疲弊】と対応させる
- 「読後に目指す状態」の3項目（安心・気づき・行動）のどれに接続するかを明示する
- 感情フローは矢印で読者の心の変化を1行で示す

---

## Step 3: 構成案の出力後に必ず実行（重要）

構成案を出力したら、**そのまま続けて**以下の形式で一次情報リストを提示する。

```
---

## ✅ 一次情報ヒアリングリスト

この構成を書くために、以下の情報を教えてください。
番号ごとに回答してもらえれば、そのまま記事に使います。

Q1. [H3名] について
→ 具体的に聞きたいこと（体験・数値・感情）を1〜2行で記述

Q2. [H3名] について
→ 具体的に聞きたいこと

（【要一次情報】フラグが付いたH3の数だけ質問する）

※ me.md にすでに記録がある場合はその旨を記載し、質問を省略する
---
```

---

## Step 4: ユーザーの回答待ち

一次情報リストを提示したら**必ず止まる**。
ユーザーの回答を受けるまで /write には進まない。

回答を受けたら：
1. 回答内容を構成案の該当H3にメモとして追記
2. 「回答ありがとうございます。/write で骨格生成に進めます」と伝える

---

## Step 5: 構成案の承認確認

ユーザーから「OK」「承認」の言葉を受けてから、
`drafts/article-XXX/outline.md` に保存する。

保存時にステータス行を追加：
```
- ステータス：承認済み（YYYY-MM-DD）
```

---

## 禁止事項

- 一次情報リストを省略しない
- ユーザーの回答を待たずに /write を開始しない
- me.md にない体験・数値を構成案に組み込まない
- KWをClaude独自に変更しない
