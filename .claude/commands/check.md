# /check コマンド｜校閲レポート生成手順書 v1.1

## このコマンドの役割

ユーザーが肉付けした `body.md` を受け取り、4つの観点でチェックレポートを生成する。
修正は行わない。問題箇所と修正方針を提示してユーザーが直す。

---

## 前提条件

`drafts/article-XXX/body.md` が存在していること。
なければ「先に /write で骨格を生成してください」と返す。

---

## Step 1: 読み込むファイル

```
drafts/article-XXX/body.md      ← チェック対象
drafts/article-XXX/outline.md   ← 構成の確認用
assets/01_ng-words.md            ← NG表現リスト
me.md                            ← 体験・数値の照合用
CLAUDE.md §4                     ← 品質基準（5原則・装飾・出典ルール）
```

---

## Step 2: チェック①｜NG表現スキャン

`01_ng-words.md` の全項目と照合し、該当箇所を列挙する。

```
【NG表現】
- 箇所：「〜することが大切です」（H2-3 第2段落）
- 修正方針：me.md §2 の数値を使い具体的な行動に書き換える
```

---

## Step 3: チェック②｜一次情報の照合

`body.md` に登場する数値・体験エピソードを `me.md` と照合する。

- `me.md` に記録があるもの → ✅
- `me.md` に記録がないもの → ⚠️【要確認】として列挙

```
【一次情報チェック】
✅ 「3,000字・4時間・50円・不採用」→ me.md §2 確認済み
⚠️ 「最初の1週間は1日3時間作業した」→ me.md に記録なし。削除または追記を
```

---

## Step 4: チェック③｜構造設計の5原則（CLAUDE.md §4-1）

以下の5原則を outline.md・body.md と照合して検証する：

```
[ ] 原則1：H2の並びが読者感情の遷移（不安→診断→判断→解決→行動）に沿っているか
[ ] 原則2：KWの「本能的な悩み3つ」に全て答えるH2が存在するか
[ ] 原則3：自己診断・選択系テーマで対比軸が2セット用意されているか
[ ] 原則4：差別化が「著者の個性」ではなく「読者の盲点」を埋める方向か
[ ] 原則5：複数属性KWでCTAが属性別に分岐しているか
```

---

## Step 5: チェック④｜装飾・SEO・出典（CLAUDE.md §4-2・§4-3）

```
【装飾チェック】
[ ] 装飾は3色以内か（黒太字・黄色マーカー・赤文字のみ）
[ ] 黄色マーカーは記事全体で1箇所のみか
[ ] 赤文字は数字強調のみか
[ ] 1段落あたりの装飾は1〜2箇所以内か
[ ] Cocoonボックスの色分けが用途に合っているか（🔴NG例・🔵OK例・🟡コツ・🟢CTA）

【SEOチェック】
[ ] 差別化ポイントが独立H2として存在するか（outline.md と照合）
[ ] 全H3がP→R→E→Pの順になっているか
[ ] リード文が500字以内か
[ ] 一文が80字を超えていないか
[ ] 同じ語尾が3連続していないか
[ ] 表が3枚以上あるか
[ ] CTAが2箇所以上あるか（リード直下・まとめ後）
[ ] 「いかがでしたか」等の禁止締め文句がないか

【出典チェック】
[ ] 数値・統計に出典リンクが付いているか
[ ] 競合引用が15文字以内・1ソース1引用以内か
[ ] 曖昧表現（「9割」「過半数」等）がないか
```

---

## Step 6: チェックレポートの出力

NG・要確認・確認項目の3段階で出力する。

```
## 校閲レポート

### NG表現（修正必須）
...

### 一次情報（要確認）
...

### 5原則チェック
...

### 装飾・SEO・出典（確認項目）
...

### 総評
問題件数：NG X件 / 要確認 X件 / 5原則違反 X件
```

レポート出力後に止まる。修正はユーザーが行う。
